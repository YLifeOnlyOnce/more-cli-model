# 阅读引导与教学路径

这份文档不是 API 手册，而是学习路线图。你可以按顺序边读边改。

## 第一阶段：先跑起来

目标：确认一个 CLI 项目从安装到运行的最短路径。

执行：

```bash
npm install
npm run build
node dist/index.js help
```

你应该观察到两件事：

- TypeScript 源码在 `src/`，但真正运行的是 `dist/` 中的 JavaScript
- 命令行参数会传给 Node 进程，再由我们的程序自己解析

## 第二阶段：看入口，理解总流程

先读 `src/index.ts`。

重点关注：

- 命令是如何注册的
- `process.argv` 是何时被读取的
- 为什么 `help` 能在任何时候兜底

你可以把入口理解成一个“总调度器”：

1. 收集所有可用命令
2. 读取用户输入
3. 找到对应命令
4. 解析参数
5. 执行处理函数
6. 输出结果并处理错误

## 第三阶段：看解析器，理解 CLI 的骨架

再读 `src/core/parser.ts` 和 `src/core/types.ts`。

这两个文件是整个项目最值得学习的部分，因为它们展示了 CLI 框架在底层至少要解决什么问题：

- 如何识别第一个词是命令名
- 如何区分位置参数和选项参数
- 如何处理 `--times 2` 这种带值选项
- 如何处理 `--upper` 这种布尔开关
- 如何做缺参报错和帮助提示

建议你自己改三个地方：

- 改一个选项名，看帮助文案是否同步变化
- 给某个命令新增一个必填参数
- 故意漏参运行，观察错误提示从哪里出来

## 第四阶段：看具体命令，理解功能扩展方式

命令都在 `src/commands/` 目录。

推荐阅读顺序：

1. `src/commands/greet.ts`：最简单，适合看命令最小结构
2. `src/commands/sum.ts`：适合看参数校验
3. `src/commands/json-pretty.ts`：适合看文件读写和业务错误处理
4. `src/commands/note.ts`：适合看本地存储与多级子命令

通过这些命令，你可以总结出一个新命令的固定模板：

1. 定义命令名和说明
2. 定义参数和选项
3. 写执行逻辑
4. 返回字符串或抛出错误

## 第五阶段：自己做一个新命令

推荐练习：新增 `time` 命令。

目标效果：

```bash
node dist/index.js time
node dist/index.js time --iso
```

你可以这样做：

1. 新建 `src/commands/time.ts`
2. 参考 `greet.ts` 写出命令定义
3. 在 `src/index.ts` 中注册它
4. 重新构建并运行

## 第六阶段：思考如何做成“真正可发布”的 CLI

当这个项目看懂后，你可以继续升级它：

- 接入 `commander` 或 `yargs`
- 接入 `prompts` 或 `inquirer`
- 接入 `chalk` 做彩色输出
- 接入 `ora` 做加载动画
- 接入 `vitest` 做测试
- 发布到 npm 并通过 `npx` 运行

## 最后你应该建立的认知

CLI 工具本质上不是神秘技术，它就是：

- 一个 Node 进程
- 一套参数解析规则
- 一组可调用的功能模块
- 一层用户输入和程序逻辑之间的映射
- 必要时再加上文件系统、网络、配置、交互能力

当你把这套模型理解透，以后不管你用原生写、用 `commander` 写，还是用脚手架写，心里都会很清楚：这些框架只是帮你省掉重复劳动，并没有改变 CLI 的本质。
